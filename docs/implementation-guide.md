# راهنمای پیاده‌سازی در ProcessMaker 3.5.8

این راهنما برای ساخت دستی فرایند بر اساس فایل README است. ترتیب اجرا را رعایت کنید.

## مرحله 1 — ساخت فرایند
1. وارد Designer شوید و یک Process جدید با نام «مدیریت درخواست خرید» بسازید.
2. سه Task بسازید: «ثبت درخواست خرید»، «تأیید مدیر»، «ثبت پرداخت».
3. دو End Event مستقل بسازید: «پایان رد درخواست» و «پایان پرداخت موفق».
4. ترتیب اتصال‌ها:
   - Start → ثبت درخواست خرید → Gateway مبلغ
   - Gateway مسیر مستقیم → ثبت پرداخت
   - Gateway مسیر مبلغ بالا → تأیید مدیر → Gateway تصمیم مدیر
   - Gateway تصمیم مدیر: رد → پایان رد؛ تأیید → ثبت پرداخت
   - ثبت پرداخت → پایان موفق

## مرحله 2 — متغیرها
در Process Variables، متغیرهای فهرست‌شده در README را ایجاد کنید. برای `quantity`, `unit_price`, `total_amount`, `payment_amount` نوع عددی انتخاب کنید. برای تاریخ‌ها Date و برای توضیحات Textarea-compatible متغیر متنی بسازید.

## مرحله 3 — فرم‌ها
برای هر Task یک Dynaform بسازید، سپس در Properties همان Task به فرم متصلش کنید. دقت کنید نام متغیر در کنترل Dynaform با نام Process Variable دقیقاً یکسان باشد. خلاصه درخواست در فرم مدیر و پرداخت فقط خواندنی باشد.

## مرحله 4 — تخصیص
- Task اول: Self Service.
- Task مدیر: Manual Assignment و انتخاب کاربر/گروه مدیر واقعی.
- Task پرداخت: Manual Assignment و انتخاب کاربر/گروه مسئول مالی واقعی.

برای مدیر و مسئول مالی از حساب Administrator به‌عنوان راه‌حل دائمی استفاده نکنید. دسترسی‌ها را با دو حساب واقعی آزمایش کنید.

## مرحله 5 — Gatewayها
Gateway اول باید بر اساس مقدار عددی `total_amount` تصمیم بگیرد:
- شرط مسیر مستقیم: `@@total_amount <= 2000000000`
- شرط مسیر مدیر: `@@total_amount > 2000000000`

Gateway دوم:
- شرط تأیید: `@@manager_decision == 'approved'`
- شرط رد: `@@manager_decision == 'rejected'`

در ProcessMaker، پنجره تنظیم شرط مسیر ممکن است بسته به نوع Gateway/نسخه، عبارت را در فیلد شرط مسیر یا متغیرهای خروجی بخواهد. عبارت‌ها را در همان محل شرط مسیر قرار دهید و مطمئن شوید هر مسیر شرط دارد و مسیر پیش‌فرض ناخواسته فعال نیست.

## مرحله 6 — اعتبارسنجی
پیش از Gateway اول، مبلغ کل را از تعداد و قیمت واحد دوباره محاسبه کنید. مقدار تعداد باید عدد صحیح مثبت و قیمت واحد عدد غیرمنفی باشد. در صورت داده نامعتبر، فرایند نباید وارد مسیر تأیید یا پرداخت شود؛ خطا باید به کاربر نشان داده شود.

## مرحله 7 — وضعیت
پس از ثبت اولیه، وضعیت را submitted قرار دهید. اگر مبلغ بالاتر از حد نصاب است، وضعیت pending_manager شود. پس از تأیید مدیر approved، پس از رد rejected و پس از ثبت پرداخت paid شود.

## مرحله 8 — آزمون
ابتدا با داده آزمایشی و حساب‌های مجزا آزمون‌های A تا H در README را اجرا کنید. تا قبل از موفقیت همه آزمون‌ها، فرایند را برای درخواست واقعی فعال نکنید.

## نکته مهم درباره PMX
PMX باید از Export خود ProcessMaker پس از ساخت و تست فرایند تولید شود. ساختن یک فایل با پسوند .pmx یا تغییر XML بدون رعایت ساختار داخلی نسخه 3.5.8، تضمین‌کننده Import یا اجرای درست نیست. پس از ساخت در Designer، از منوی Export همان Process خروجی بگیرید.
